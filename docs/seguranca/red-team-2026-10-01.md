## Matriz RLS (agrupada)

As 151 tabelas seguem um padrão de autorização uniforme (helpers `private.*`: `papel_na_unidade`, `eh_super_admin`, `unidades_do_usuario`). Listado o padrão por grupo + **todas** as exceções individualmente.

| Grupo | SELECT | INSERT | UPDATE | DELETE | Veredito |
|---|---|---|---|---|---|
| Backbone (organizacoes, unidades, perfis, vinculos, setores, leitos, log_auditoria, super_admins) | super / admin-org / membro | super / admin-org | idem + **anti-self** em vinculos (`perfil_id <> meu_perfil_id()`) | super | **OK** — teste live: `INSERT super_admins` e `INSERT vinculos gestor` como authenticated → `42501 RLS violation` |
| Clínico (~120 tabelas: pacientes, prescricoes, prescricao_itens, internacoes, observacao, evolucoes, exames, pareceres, cuidados, administracoes, atendimento…) | super OR gestor OR plantonista-no-cuidado | idem + RESTRICTIVE `segundo_fator_ok()` em 12 tabelas | super / gestor / médico-autor plantonista | super / gestor | **OK** — keyed em `papel_na_unidade`; teste live: recepcao lê `pacientes/prescricoes/internacoes/documentos` → `[]` |
| Referência global (medicamento, cid_*, lnnc_*, classe_alergenica*, ferramentas_clinicas, ferramenta_versoes, protocolos_observacao, especialidades_parecer) | `true` | super | super | super | **OK** — sem coluna de tenant = dado global; `true` aceitável |
| `configuracao_plataforma` | `true` (authenticated) | — | — | — | **Fraca/info** — expõe flags da plataforma (ex.: 2FA) a qualquer logado. Baixo |
| Zero-policy / deny-all (18: hermes_*, erros_cliente*, admissao_*, chamados_tecnicos*, painel_*, receita_protocolos*, ferramenta_unidade, responsaveis_tecnicos, cerbero_url_cache, termos_cancelamentos) | deny | deny | deny | deny | **OK por design** (só service_role / SECURITY DEFINER; "falha fechada") — depende de V1 |

## Cenário encadeado (pior caso realista)

1. Atacante entra como `plantonista` legítimo (código de convite enumerado — Achado 1 do pentest anterior, mitigado mas a classe existe; ou credencial de colega).
2. Estação de UPA compartilhada: abre DevTools, lê `cc:rascunho:*` (V6) → PHI de pacientes do turno anterior (nome, diagnóstico, alergias).
3. Via `registrar_prescricao_itens` (V3), reescreve itens de uma prescrição assinada por OUTRO médico; `medico_id` permanece o do médico real.
4. A prescrição adulterada sai com autoria falsa do médico vítima (receita/atestado com itens trocados).
5. Usa `solicitar_troca` (V4) para assumir plantões-chave sem aprovação, ampliando a janela de acesso a mais pacientes.
6. No chat Hermes, escreve o nome do paciente em minúsculas (V5) → vaza a provedor LLM offshore.
7. Resultado: adulteração clínica imputada a terceiro + exfiltração de PHI + manipulação de escala — tudo com **um** papel baixo, sem tocar a RLS (que resistiu a todos os testes diretos).

Nota: a RLS/autorização de banco **não** é o elo fraco. Os elos são 2 RPCs com checagem incompleta (V3/V4), PHI no cliente (V6) e desidentificação por regex (V5).

## Dívida estrutural (3 decisões que gerarão falhas novas mesmo após corrigir tudo)

1. **Hermes com service_role cru + autorização reimplementada em código (V1).** Sem backstop de RLS, cada nova tool/skill é uma chance de vazamento cross-tenant que o banco não barra. Enquanto existir, toda feature do agente é superfície crítica.
2. **`GRANT ALL` a `authenticated` em todas as tabelas, RLS como único portão.** Grants largos significam que cada tabela/coluna/RPC nova nasce exposta até alguém escrever a policy/guard perfeita. V2 é exatamente essa classe (função sem guard de topo) — vai repetir. Mitigação: grants mínimos por tabela + teste de policy obrigatório no CI para cada tabela nova.
3. **Desidentificação por regex antes de LLM offshore (V5).** Abordagem fundamentalmente incompleta (nomes em prosa escapam). Cada novo campo de texto livre é um novo vetor de vazamento de PHI para fora do Brasil. Precisa de NER + allowlist estrita, ou LLM on-shore/on-prem para dado clínico.

## Defesas que resistiram (verificadas, não assumidas)

- RLS em 151/151 tabelas; nenhuma confia papel via JWT.
- Escalonamento bloqueado (teste live `42501`): `super_admins` INSERT = `eh_super_admin()`; `vinculos` INSERT/UPDATE anti-self.
- recepcao não lê pacientes/prescrições/internações/documentos de nenhuma unidade (`[]`), não enumera vínculos nem perfis, não chama `gerar_convite`.
- Censo/indicadores filtram por `unidades_do_usuario()` + k-anonimato (sem cross-tenant).
- 2FA (aal2) completo: 56 RPCs SD de escrita clínica, 0 sem gate (verificado no catálogo).
- `SECURITY DEFINER` sem `search_path`: 0 (item ago/2026 corrigido, 598 blocos varridos).
- `authenticated`/`anon` sem CREATE em `public`/`private`.
- Storage: buckets clínicos privados e escopados por unidade/papel; `receitas`/`fotos` sem policy (só signed URL/service_role).
- Webhook (ago/2026 "sem verificação de origem"): corrigido — Hermes HMAC-SHA256 + `timingSafeEqual`; notify-email `Bearer <WEBHOOK_SECRET>` fail-closed.
- clinical-search: gateway de desidentificação fail-closed + rate-limit 30/h + validação de unidade por vínculo.
- Alta, assinatura (CRM próprio), farmacêutico (não edita conteúdo clínico), timestamp de ADT (server now() + hash-chain) e `log_auditoria` (append-only): autorização enforçada no banco.
