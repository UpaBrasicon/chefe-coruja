## 2. Security posture

Inside `src` the client does not act as a security boundary on its own, and the hunters confirmed the server re-checks the unit, role and patient parameters the browser sends. React escaping holds everywhere except the print pipeline, and no `dangerouslySetInnerHTML` exists. The leads that remain are about what the browser keeps and opens: a server-ended session that leaves the previous user's keys and caches in the tab, an attachment window that keeps `window.opener` while the `atendimento` bucket accepts SVG/HTML, the unescaped consent-form title in the print header (same root cause as run-1), offline replay that trusts the client's "was offline" claim, and chat messages readable without the second factor once 2FA is switched on. Each needs a homologation check before it is called a vulnerability.

## 3. Confirmed findings

None. No candidate could be executed under the required sandbox, so none meets the confirmed contract.

## 5. Hardening notes (not findings)

- chat_msg_select (supabase/migrations/20260817000002_fase4_chat.sql:97) does not require an active vinculo despite its comment, and nothing removes conversa_participantes when a vinculo is deactivated. A removed staff member keeps reading their 1:1 history and any new message the other side sends. Consider an active-vinculo term or participant cleanup on deactivation.
- AppShell.tsx:225/402: the client 2FA gate treats a segundo_fator_status error as pass. Server enforcement makes this UX-only today, but failing closed (show the gate or a retry) would stop subscriptions like chat-global from running before 2FA.
- UnidadeContext.tsx:96 falls back to a cached isSuper flag on network failure; it is UI-only (RPCs re-check eh_super_admin) and kept per-tab, but worth noting if any new screen trusts ehSuperAdmin to skip a server call.
- src/lib/folhas.ts:1126 relPareceres passes p.especialidade and p.status raw as Ficha.sub. It is not exploitable today because especialidade is a FK to the fixed especialidades_parecer catalog, but cabecalho() should esc() doc and sub itself so callers cannot forget.
- Error text (RPC error.message / r.erro) is written raw into print popups at src/lib/prontuario.ts:167,232,270,301,316, LaudoAih.tsx:153, FichaAdmissao.tsx:152,229 and ReavaliacaoQuadro.tsx:52. No attacker-controlled source was found, but these should be escaped as pulseira.ts and ImpressaoProntuario.tsx:283 already do.
- Print popups (window.open('', '_blank') in prontuario.ts, pulseira.ts, LaudoAih, FichaAdmissao, ReavaliacaoQuadro, ImpressaoProntuario) keep window.opener. The parent keeps its own reference, so setting janela.opener = null right after opening would not break printing and would remove the tabnabbing leg of any future injection. Adding Cross-Origin-Opener-Policy: same-origin-allow-popups to vercel.json would also help.
- Banner link_url (public.banners) has no server-side https CHECK; only zod .url() validates it, and that accepts javascript:. React 19 and the CSP block execution today. Add CHECK (link_url ~ '^https://') like definir_link_imagem does for exam images.
- ImpressaoProntuario.tsx:61 local esc() does not escape apostrophes. It is safe in its current text-node uses; reuse escapeHtml from src/lib/utils.ts instead.
- SegundoFator.tsx:22-31: the trusted-device token cc_dispositivo_2fa is a bearer token kept in localStorage across logout. The server binds it to the user (verificar_dispositivo_2fa checks user_id), but anyone at a shared computer can copy it and, together with that user's password, skip the email code from another machine. Consider binding it to a non-exportable device key or offering 'confiar' only when 'manter conectado' is on.
- fila.ts:155-169: legacy device-generated queue keys in the IndexedDB 'chaves' store are removed only when the same person logs in again; unsynced legacy items of people who never return stay decryptable by a same-origin script on that profile. A one-time purge of the 'chaves' store, or of entries older than the migration, would close this.
- supabase.ts:65-69 and AuthContext.tsx:100-102: the 12-hour 'manter conectado' limit is checked only on page load; a tab left open keeps refreshing the session past 12 h.
- supabase.ts:88-90: 'manter conectado' is remembered per browser, not per person, so the next user on a shared computer gets the previous user's choice preselected.
- useChaveFila.ts:20-31: trocar_chave_fila (lost device, O5) rotates the server key, but an open tab keeps the old key in memory and in sessionStorage until it re-fetches on remount.
- higienizar (src/lib/reportarErro.ts:49-57) is a denylist covering only e-mails, UUIDs, CPF and long digit runs; personal names and free text pass. Today MensagemErro forwards raw non-P0001 server messages (erros.ts:32), and Postgres errors such as 22P02/22007 echo the offending input value. Prefer reporting only SQLSTATE plus a fixed label for server errors (as fetchComRelato already does) instead of the message text.
- The Sentry tag 'unidade' sends the active unit UUID (sentry.ts:45). It is not PHI, but it contradicts the 'unidade nao vai' note for metrics. Keep it only if needed for triage.
- Buckets 'banners' (public) and 'fotos' have no allowed_mime_types while the client passes file.type as contentType (src/lib/api.ts:261-265, src/pages/Perfil.tsx:161-165). Banner upload is gestor-only, but a public bucket accepting arbitrary types can host spoofed content under the project domain. Add an image allowlist.
- src/pages/Perfil.tsx:170 calls getPublicUrl on the private 'fotos' bucket; the saved URL will not load (functional defect, no data exposure).
