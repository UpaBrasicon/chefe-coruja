## 2. Security posture

Across the three runs the database core held: guarded RPCs, bound helper ids, a fail-closed AI de-identification gateway and a correctly bound RNDS certificate vault. This review found the weakest layer is unit membership and identity. The `vinculos` policies let any organisation admin attach any user from any tenant with any role, which is broader than the run-1 reset lead. The `perfis_select` policy lets any organisation admin read CPF and contacts of every unlinked user platform-wide. Contract adhesion happens before e-mail ownership is proven. The second factor is also uneven: 11 clinical tables and the `clinical-search` edge function do not check it, although that only matters once `exigir_segundo_fator` is on, and it ships off. Secondary leads are document types emitted through generic paths, a patient name re-sent to the model in assistant history, and a root cron that deploys whatever `master` holds. All are `needs_validation`: one homologation check each decides them.
